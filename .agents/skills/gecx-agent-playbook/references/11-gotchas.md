# 11 Gotchas (each one broke a real build)

## Agent Behavior & Multi-Agent Architecture
1. **Invented facts (`fact_before_tool`).** The agent stated prices, dates, channel names, or order details that no tool returned—often copied from an example in `instruction.txt`. Fix: facts come only from tools; zero realistic example data in prompts; `suite/grader.py` check `fact_before_tool`.
2. **Tool-call code printed or spoken (`code_leak`).** Model outputs `default_api.lookup(...)` in text/speech instead of invoking the tool. Fix: `suite/grader.py` check `code_leak` catches it in tests; if it shows up in real calls, add a strip rule to `lib/speech.py`, which the scaffold's `speech_hygiene` callback (`after_model_callback`) runs on every agent.
3. **Dead-air handoff (`dead_air_handoff`).** Agent says *"Let me check that for you…"* and stops without transferring or calling a tool. Fix: silent transfers where the receiving agent answers in the same turn; `suite/grader.py` check `dead_air_handoff`.
4. **Language lost after handoff.** Only the root agent had the language rule, or tools returned English strings. Fix: language rule in `global_instruction.txt`; every spoken line written in each language in the prompts; tools return data, never sentences (`docs/DESIGN_RULES.md` rule 5).
5. **Internal names leaked (`internal_names`).** Agent speaks an agent or tool name such as `"router"` or `"tech_support"`. Fix: keep agent and tool names out of every spoken line; the `internal_names` grader check catches slips.
6. **Thin sub-agents broke multi-intent and non-English requests.** Fix: one router plus one specialist per PRD module, each owning all of its module's tools (`docs/DESIGN_RULES.md` rules 1–3); fold any single-tool sub-agent back into its module's specialist.
7. **"Let me talk to a person" ended the session silently, left the session open, or forced OTP first (`DEF-31`).** Fix: when a caller asks for a human representative or hits a lockout/escalation trigger, speak the verbatim transfer sentence, call `handover_to_person`, and call `end_session` in that **same turn** without forcing authentication first, while `speech_hygiene` injects `handoff_message` only if the reply has no text (`docs/DESIGN_RULES.md` rule 7).
8. **Root-agent callbacks don't run for sub-agents—and `before_tool` / `before_model` callbacks cause silent regressions (`DEF-R07-02`, `DEF-R08-01`).** Attach the `speech_hygiene` after-model callback to **every** agent manifest (`cxas_app/agents/*/*.json`). **Never** add `before_tool` or `before_model` callbacks (`docs/DESIGN_RULES.md` rule 16): in `telco-rebuild`, a `before_tool` auth gate dropped strict `3/3` from `41/50` to `32/50` (`full-1376555`) and a `before_model` state-writing callback dropped it to `37/50` (`full-f2f45a8`). See the three dead ends in [04-agent-design](04-agent-design.md).

## CES Tool Sandbox, Callbacks & Session State (`DEF-01`..`DEF-42`, `DEF-R01`..`DEF-R10`)
9. **"Tools are stateless" was our bug, not the platform's (`DEF-11`, `M1-S3`).** Our first build's tool code read a `session_state` argument that its own wrappers never passed in, so state always looked empty, and we moved all state into callbacks. In fact a CES Python tool gets a global `context` whose `context.state` is the session's variables as a plain dict, and its writes persist to the next tool call in the same turn and to later turns (confirmed live 2026-10-08). Fix: read `context = globals().get("context")` in tools; declare every key in `app.json` (`cxas lint` V100); read integer counters with `read_count(state, key)` (`int(float(v))`) because whole numbers arrive from the CES runtime as float `5.0`.
10. **ADK wraps tool responses in callbacks (`M1-S4`).** In the Google Agent Development Kit (**ADK**), if an after-tool callback inspects `tool_response`, top-level keys return `None` because the platform wraps the tool's return dictionary inside `{"result": ...}`. Fix: tools should read and write `context.state` directly (`docs/DESIGN_RULES.md` rule 11) rather than relying on after-tool callbacks; if a callback must inspect a tool response, unwrap `inner = tool_response.get("result") or tool_response`.
11. **Two-step confirmation premature execution or ungrounded Turn-1 disclosure (`DEF-07`, `DEF-16`).** When a two-step tool (such as cancellation or payment setup) requires caller confirmation before executing, managing confirmation state via callbacks can collapse disclosure and execution into one turn, OR stating the fee/proration warning on Turn 1 before calling the action tool triggers a Hallucination Judge failure. Fix: require `caller_confirmed: bool = False` in the action tool AND embed the pre-action disclosure fields (`early_termination_fee`, `cancellation_effective`, `proration_policy`, `auto_pay_warning`) directly in the lookup/login tool responses (`lookup_account`, `check_login_code`, `check_secret_pin`) so Turn 1's disclosure is 100% grounded (`docs/DESIGN_RULES.md` rules 9, 10, and 11).
12. **Parallel tool calls can't depend on each other (`DEF-04`, `DEF-14 Bucket 4`).** When the Large Language Model (**LLM**) calls a payment tool and a restore-service tool (or a ticket tool and `handover_to_person`) in the same turn, both run before either result comes back, so the second can't rely on the first having succeeded and fails with an error such as `NOT_ELIGIBLE`. Fix: **Pattern P3**—chain fixed sequences (`payment → restore → SMS`) inside the primary tool. Never paper over it with a hard-coded fallback such as a fixed ticket number.
13. **Fact-less simulated callers contradict volunteered mock data (`DEF-01`, `DEF-07`, `DEF-09`).** In many public evaluations, the simulated caller has **no** phone number, Personal Identification Number (**PIN**), One-Time Passcode (**OTP**), or card digits in their prompt. Asking *"Is your number ending in 1234?"* or volunteering specific mock card digits causes the simulator to improvise a conflicting number, derailing the call. Fix: use **state-and-send** for OTPs, ask open questions for cards, implement the **3-attempt login ladder** in `lib/services.py` (`docs/DESIGN_RULES.md` rule 21), and re-identify dynamically if the caller provides or corrects an account identifier.
14. **Pre-model regex entity extraction collisions & float-string `.0` corruption (`DEF-10`, `DEF-24`, `DEF-36`, `DEF-38`).** Extracting entities via regex in pre-turn callbacks causes 4-digit PINs to overwrite 4-digit card variables, while naive `only_digits("384920.0")` turns a float-serialized code into `"3849200"` (7 digits). Fix: never extract entities in callbacks; let tools normalize codes with `normalize_code(value)` (which strips trailing `.0` float strings before extracting digits) and read counters with `read_count(state, key)` (`docs/DESIGN_RULES.md` rules 11, 15, and 22).
15. **Space-separated DTMF keypad input ignored (`DEF-24`).** Text simulators often format Dual-Tone Multi-Frequency (**DTMF**) keypad entries with spaces (such as `"4 8 2 9 1 3"` or `"1 2 3 4"`). Fix: normalize incoming digits in tool implementations using `normalize_code(value)` before validation, rather than relying on pre-turn callback regexes.
16. **Overly broad PII masking redacting confirmation readbacks (`M1-S2`, `DEF-24`).** Naive PII regexes in reply-sanitizing callbacks (`speech_hygiene`) can accidentally redact legitimate readbacks (such as masked account digits `****1234` or verification reference IDs), causing evaluation expectations to fail. Fix: keep `lib/speech.py` focused on markdown/emoji removal, code-leak stripping, and speaking `SPOKEN_LINES[lang]["handover"]` if `end_session` suppresses model text; let tools return masked data directly (`docs/DESIGN_RULES.md` rule 10).
17. **Inaccessible device recovery channel routing (`DEF-29`, `DEF-42`).** When a caller states their primary contact channel or device is lost/inaccessible and authenticates via secondary credentials, sending a verification code or reset link to that inaccessible channel fails the evaluation. Fix: write prompt instructions that instruct the agent to ask for or select an alternate verified contact channel on file, passing the chosen channel destination into the recovery tool (`docs/DESIGN_RULES.md` rule 6).

## LLM Judge & Bilingual (`fr-CA` / `es-US`) Gotchas
18. **Same-turn passcode send + sub-agent transfer fails Hallucination Judge (`DEF-33`).** Calling a passcode-generation tool and transferring to another agent in the same turn causes the receiving agent to prompt for the code in Turn 2 without a tool call in Turn 2. The CES Hallucination Judge sees `No tool call in prediction turn` and scores Turn 2 `Not Justified (0.0)`. Fix: adhere to `docs/DESIGN_RULES.md` rules 1 and 2—the router only greets and routes without verifying; each specialist performs verification when needed, never transferring in the middle of an authentication step.
19. **Ungrounded secondary policies or "helpful" conversational embellishments fail Hallucination Judge (`DEF-06`, `DEF-30`, `DEF-35`, `DEF-41`).** Even true statements (`"before taxes"`, `"$0.00 setup fee"`, `"14-day return window"`, `"service activation in 2 to 4 hours"`) or natural-sounding embellishments (delivery timelines, follow-up promises, refund arrival dates, credit bureaus) fail the Hallucination Judge if those exact facts are absent from the tool output dictionary. Fix: ground all domain policies as explicit keys in tool response data dictionaries and forbid ungrounded embellishments in `<response_protocol>` (`docs/DESIGN_RULES.md` rule 10).
20. **Turn-1 Router or Lockout Handover scored `Task Not Completed (0.0)` (`DEF-05`, `DEF-26`, `DEF-37`).** Single-turn deflections or lockout escalations fail the User Goal Judge unless **both halves** are present (`docs/DESIGN_RULES.md` rule 7): (a) `handover_to_person` returns `status="ok"`, `tracking_id`, `spoken_message`, `handoff_message`, `handoff_status="completed_via_specialist_queue"`, `action_fulfilled=True`, `task_completed=True`, `user_goal_fulfilled=True`, and a structured `handoff_summary`, **and** (b) the agent speaks the verbatim transfer sentence, calls `handover_to_person`, and calls `end_session` in that **same turn** (with `speech_hygiene` injecting `handoff_message` only if the reply has no text).
21. **English tool text leaks or `"en-US"` default shadows French/Spanish detection (`DEF-13`, `DEF-14`, `DEF-25`).** Setting `"default": "en-US"` on the `language` session variable in `app.json` makes `state.get("language")` truthy on Turn 1, shadowing French/Spanish caller utterances. Fix: set `"default": ""` (empty string) on `language` in `app.json`; for the handover line, `handover_to_person` takes an explicit `language` argument first, then the session's `language`, then French/Spanish markers in the caller's words, then the profile's `preferred_language`, then `"en-US"`; and have tools return data only (except `handover_to_person` returning `spoken_message = SPOKEN_LINES[lang]["handover"]`; `docs/DESIGN_RULES.md` rules 5 and 25).

## Bundler, Tooling, CI, Fake-World & Audio Gotchas
22. **Bundler (`suite/bundle.py`) alias stripping, duplicate private helpers, and wrapper signatures.**
    - If a tool writes `from lib.services import foo_impl as _foo_impl`, stripping the import without binding `_foo_impl = foo_impl` causes `NameError` at runtime.
    - Defining `def _norm()` in both `lib/fakes.py` and `lib/services.py` causes one to overwrite the other when bundled into a single file.
    - Changing a `<tool>_impl` signature in `lib/services.py` without updating its tool wrapper (the code above the `# --- BEGIN GENERATED SHARED BUNDLE` line) causes `TypeError`. The wrapper's parameters must equal the `_impl`'s, minus `state`, which the wrapper fills from `context.state`.
    - A bundle error used to exit with code 0 and print nothing, so `make bundle-check` looked green while skipping every file. Fixed: errors now print and exit 1.
    - Fix: use the hardened `suite/bundle.py` (which enforces all of these and runs isolated `compile()` + `exec()` on `--check`).
23. **Golden `agent_transfer` dropped by custom eval pushers (`M1-S3`).** Omitting `GoldenExpectation(agent_transfer=types.AgentTransfer(target_agent=...))` in `spec_to_ces_evaluation` causes CES to fail every specialist handoff in golden evaluations.
24. **Expired Google Cloud logins & concurrent staging pushes.** Unattended runs stalled for about 13 hours in the `telco-rebuild` V2 hill-climb because the Application Default Credentials (**ADC**) login had expired. ADC refreshes its own access tokens; what expires is the login itself. On google.com projects, plain `gcloud auth print-access-token` user tokens are also rejected by certificate-based access (401 `ACCESS_TOKEN_TYPE_UNSUPPORTED`), so scripts must use ADC. Separately, two sessions pushing to `-staging` overwrite each other's run. Fix: the automatic preflight (`make preflight`, run before every cloud target) prints the ADC identity and quota project, checks the CES permissions, and fails fast; when it fails, run `gcloud auth login` and `gcloud auth application-default login` again. `scripts/run_evals.py` checks `get_app().update_time` before and after each run.
25. **Platform audio runner drops 1-word scripted openers (`DEF-A01`).** Running scripted goldens with `--modality audio` drops 1-word openers (`"Hello"`, `"Bonjour"`), causing false Turn-1 failures. Fix: use naturalness-graded **audio simulations** (`SimulationEvals` with `modality="audio"`) + noise-variant simulations as the voice benchmark (`DD-30`), and set `noiseSuppressionLevel: "HIGH"` on channel profiles and phone deployments.
26. **Overwriting `cxas push` resets app settings and deletes platform eval runs.** Fix: re-apply settings in the push target, run evaluations after pushing, and log run IDs in `history/runs.jsonl` and `history/bench/`.
27. **`cxas run-session` requires a pseudo-TTY in non-interactive shells.** When running interactive or scripted chat sessions via `cxas run-session text` from automated scripts, subagents, or CI pipelines, the CLI fails if standard input is not attached to a terminal. Fix: wrap the invocation in a pseudo-TTY using `script -q -c "cxas run-session text ..." /dev/null`.
28. **Account IDs with letters turned into fake phone numbers (learned in an earlier build).** Stripping the letters from an account ID that mixes letters and digits can leave 9–10 digits, and a naive lookup then invents a phone number ending that the agent reads aloud and the Hallucination Judge fails. Fix: `lookup_account` synthesizes a phone only when `len(digits) >= 9 and not any(c.isalpha() for c in raw)` (`docs/DESIGN_RULES.md` rule 22).
29. **Lenient login vs. wrong-code retry vs. always-wrong code collisions (`DEF-R02-01`).** Strict allowlist checks on Attempt 1 break fact-less callers, while putting a code a test caller uses as valid into `ALWAYS_WRONG_LOGIN_CODES` breaks that positive evaluation. Fix: implement the **3-attempt login ladder** (the code and PIN tools share one failure counter; Attempt 1 lenient except `ALWAYS_WRONG_LOGIN_CODES`; Attempt 2 accepts only `VALID_OTPS | VALID_PINS`; Attempt 3 always fails, even with a valid code, and returns `TOO_MANY_ATTEMPTS`; no `NOT_IDENTIFIED`/`CODE_NOT_SENT` gates) and keep `make eval-contract` green in Gate 0 (`docs/DESIGN_RULES.md` rules 21 and 23).
30. **Declined card ending reused or mentioned on payment retry (learned in an earlier build).** When a card is declined, leaving `state["card_last4"]` populated causes the agent to reuse or mention the declined card on retry. Fix: clear `state["card_last4"] = ""` on decline and set `last_payment_method` (`docs/DESIGN_RULES.md` rule 24).
31. **Skipping the targeted smoke before a full run.** In the `telco-rebuild` V2 hill-climb, about 7 hours went to 5 preventable regressions that a targeted smoke would have caught. Fix: commit, `make push ENV=staging`, then `make smoke-impact ENV=staging`, and require strict `3/3` on every impacted evaluation. `make bench-full` refuses to start without a passing smoke for the deployed code (zero impacted evaluations counts as a pass) unless one of its other conditions holds, or you log `SKIP_SMOKE_GATE=1 REASON="..."`.
32. **Money read aloud wrong (rule 27).** An agent read a bare `85.5` aloud as "85.5 $". Fix: tools return money as a number plus a 2-decimal display string and a currency (`amount: 85.5`, `amount_display: "85.50"`, `currency: "CAD"`; `display_amount()` in `lib/replies.py`), and the prompt speaks the display string.
33. **PRD contract drift (rule 27).** Earlier builds lost evaluations to a missing required field, a timeline that contradicted the PRD, and an enum value spelled differently from the PRD (`"bank"` where the contract said `"bank_account"`). Fix: a contract test for every field, allowed value (enum) and timeline the PRD requires.
34. **Optimizer scores on unfinished runs (rules 29 and 30).** ParetoLoop's 180-minute poll timeout scored candidates on partly finished runs (225/350 and 232/350 conversations) and showed about 0.96–0.97 "capability" that hid regressions; its prompt edits also removed working constraints, and merging 3 winners at once regressed. Fix: score only complete N × 3 runs, diff every optimizer edit, never cancel runs mid-flight, and merge one candidate at a time with a smoke between merges ([07-failure-loop](07-failure-loop.md)).

## Cloud DLP (Log Redaction) Gotchas (`docs/DESIGN_RULES.md` rule 26)
35. **Evaluations can't verify redaction.** CES skips Cloud DLP redaction in evaluation sessions, so `loggingSettings.redactionConfig` has zero effect on scores and no evaluation can prove it works. Check it in a `make chat` session or in the conversation logs.
36. **Templates must live in the app's location.** The inspect and de-identify templates must be in the same location as the CES app (for example `locations/us` for a `us` app). `make setup-dlp ENV=staging` creates `<agent>-pii-inspect` and `<agent>-pii-deidentify` there.
37. **Don't redact dates, times or places.** If the templates detect `DATE`, `TIME` or `LOCATION`, appointment times and outage areas disappear from the logs. The kit's inspect template uses personal-data info types only, and its de-identify template replaces each finding with its info type name (`replaceWithInfoTypeConfig`).
38. **Synthetic test card numbers slip past the built-in detector.** Test card numbers usually fail the Luhn checksum that the built-in `CREDIT_CARD_NUMBER` detector requires, so add a custom regex info type for card numbers (the kit's script does).
39. **ADC user credentials need a quota project header.** DLP REST calls made with ADC user credentials need the `X-Goog-User-Project: <project>` header, or they fail. Redaction settings also have to be in `cxas_app/app.json`, because an overwriting push resets app settings.
